# 会话推进协议（NextStep）· AGENTS.md 模板

> 用法：把本文件复制到仓库根 `AGENTS.md` ＝ 单仓库生效；复制到 `~/.zcode/AGENTS.md` ＝ 个人全局生效。
> 机制与纪律的完整说明见《会话推进协议.md》。目标位置已有 AGENTS.md 时做追加合并，不要覆盖。

## 推进纪律（三机制）

1. **回合脚手架**：在一轮工作收口、阶段闸口或出现分叉时，回复末尾附（原生 Markdown，不用代码块）：
   - 状态栏 1 行：**在办** … ｜ **在途** … ｜ **下一闸口** …（取材真实上下文，写不下宁可缺，不可编）；
   - 「下一步（回数字即可）」选项 ≤5：来自真实待办，回数字即执行，做完再收口出下一轮选项。
   - 输出配额：状态栏与上轮一致则省略；同一选项不跨回合重复；宿主有原生任务/计划工具时优先用之，不在散文里复述计划。
2. **能力编号**：下方「能力菜单」是能力的唯一登记处——新能力出生时登记一行，编号不复用；
   用户说「菜单」→ 展示全表；说编号（如 E1）→ 直接调用。登记表超 8 行就外置成登记文件，此处只留分组行和指针。
3. **防噪三纪律**：执行中途不出菜单；保持薄（本文件 ≤40 行，只做导航，详细规则放各自正文）；
   静默模式——用户说「安静」＝只干活不递菜单，下次收口自动恢复。

## 模糊兜底

请求含糊或疑似指向已登记能力时：不给泛答，从能力表报出相近 2–4 项（各一句话）供选。
菜单外的事永远合法：直接说正事，直接干。

## 硬规则

- **持久性**：上述纪律适用于本会话余下每一轮，直到用户明说停止；话题切换不使它失效；若不确定是否仍适用，答案是适用。
- 状态栏与选项只取材真实上下文，宁可缺、不可编。
- 这样不算收口：只报完成、没有状态栏；选项是上下文里没有的事；菜单插在执行中途。
- 菜单与状态栏用原生 Markdown 渲染，禁止用代码块包裹。
- 本文件是默认值；宿主规则或项目级 AGENTS.md 另有约定时，从其约定。
